# Proposed revisions for review

These changes are recommended by the observed failures. They are not active instructions and have not been tested.

1. Output format: explicitly list the 13 permitted response keys. Explain that schema metadata ($schema and title) is not part of the response instance. Keep the frozen schema and tools unchanged.
2. Abstention precedence: before classification, check whether a usable system, comparator and credible evidence are identified. If not, abstain from all category assignments. Apply the Incremental default only after an adequately specified technology can be assessed.
3. Scope stability: define the general technology boundary and baseline once. Application-specific model configuration, clinical inputs and customer-service tasks belong in application_finding, not the general boundary.
4. Posture: explain which evaluation stage, evidence threshold or pace changes under conservative posture. Do not require a different final action when the unchanged evidence reasonably supports the same action.
5. Verification: rerun all five prompts in new conversations after a versioned revision. Preserve these failures and keep pre/post runs separate. A formatting repair to a saved reply is not a model retest.
